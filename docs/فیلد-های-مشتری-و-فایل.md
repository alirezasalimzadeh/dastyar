# فیلدهای مشتری و فایل — دستر

سند مرجع کامل فیلدها بر اساس کد فعلی اپلیکیشن (مه ۱۴۰۵).
مهم‌ترین نکته: اطلاعات «مالی و مشخصاتی» مشتری در ستون‌های بالای جدول نیست؛
**به‌ازای هر نوع ملک** در فیلد JSON `property_preferences` ذخیره می‌شود
(کلید همان نوع ملک مثل `apartment` است).

---

## بخش اول: مشتری (جدول `customers`)

### ۱. اطلاعات اصلی
| فیلد | کلید | توضیح |
|---|---|---|
| نام و نام خانوادگی | `name` | الزامی |
| موبایل | `mobile` | الزامی، فرمت 09xxxxxxxxx |
| تلفن ثانویه | `secondary_phone` | اختیاری |
| آدرس کامل | `property_preferences.address` | در فرم داخل تنظیمات ذخیره می‌شود (ستون `address` قدیمی) |
| آدرس (قدیمی) | `address` | فقط داده‌های قدیمی |

### ۲. معامله
| فیلد | کلید | مقدارها |
|---|---|---|
| نوع معامله | `transaction_intention` | `buy` خرید، `rent` اجاره، `sell` فروش، `partnership` شراکت |
| نقش در معامله | `transaction_role` | `buyer` خریدار، `seller` فروشنده، `owner` مالک، `applicant` متقاضی، `builder` سازنده |
| دسته‌بندی | `preferred_category` | `residential` مسکونی، `industrial` صنعتی، `agricultural` کشاورزی، `commercial` تجاری، `office` اداری |
| انواع ملک موردنظر | `preferred_property_types` | آرایه از ۲۰ نوع (جدول پایین) |
| شهرهای موردنظر | `preferred_city_ids` | آرایه id شهر |

### ۳. موقعیت (داخل `property_preferences.location`)
| فیلد | کلید | توضیح |
|---|---|---|
| شهرستان | `county_id` | از جدول `counties` (مفعل‌ها) |
| محله | `neighborhood_id` | فقط برای روباط‌کریم (از جدول `neighborhoods`) |

### ۴. فیلدهای مالی — **به‌ازای هر نوع ملک** (داخل `property_preferences.<type>`)
| نوع معامله | فیلدها |
|---|---|
| خرید / فروش | `budget_min` حداقل بودجه (تومان)، `budget_max` حداکثر بودجه (تومان) |
| اجاره | `deposit_min` حداقل ودیعه، `deposit_max` حداکثر ودیعه، `rent_min` حداقل اجاره ماهانه، `rent_max` حداکثر اجاره ماهانه |
| شراکت (متقاضی) | `land_value` ارزش زمین (تومان)، `expected_share` سهم مورد انتظار (درصد) |
| شراکت (سازنده) | `construction_budget_min` حداقل بودجه ساخت، `construction_budget_max` حداکثر بودجه ساخت، `construction_share` سهم ساخت پیشنهادی (درصد) |

> ستون‌های قدیمی `budget_min` / `budget_max` در سطح بالای جدول برای داده‌های جدید پر **نمی‌شود**.

### ۵. فیلدهای مشخصات ملک — **به‌ازای هر نوع ملک**
| نوع ملک | فیلدها |
|---|---|
| آپارتمان / مستغلات | `min_area` حداقل متراژ، `max_area` حداکثر متراژ، `min_rooms` حداقل اتاق |
| خانه ویلایی / ویلا / پنت‌هاوس | `min_area`، `max_area`، `min_rooms`، `land_area` حداقل متراژ زمین، `building_area` حداقل زیربنا |
| برج / سوئیت | `min_area`، `max_area`، `min_rooms`، `total_floors` تعداد کل طبقات، `units_per_floor` تعداد واحد در هر طبقه |
| کلنگی | `min_area`، `max_area`، `frontage` حداقل بر/دهنه، `facing` جهت مورد نظر، `has_commercial` تجاری می‌خواهد؟، `max_build_floors` حداقل قابلیت ساخت (طبقه) |
| زمین مسکونی / زمین تجاری / زمین صنعتی | `min_area`، `max_area`، `frontage`، `facing`، `needs_permit` جواز ساخت می‌خواهد؟ |
| مغازه | `min_area`، `max_area`، `frontage` |
| غرفه داخل پاساژ | `min_area`، `max_area`، `floor` طبقه مورد نظر |
| زیرزمین تجاری | `min_area`، `max_area` |
| باغ و باغچه | `min_area`، `water_quota` سهمیه آب مورد نیاز |
| زمین کشاورزی | `min_area`، `max_area`، `frontage`، `facing`، `needs_permit` |
| آپارتمان اداری | `min_area`، `max_area`، `min_rooms` |
| کارخانه / کارگاه / سوله / انبار / گاراژ | `min_land_area` حداقل متراژ زمین، `max_land_area` حداکثر متراژ زمین، `min_hall_area` حداقل متراژ سالن، `road_width` حداقل عرض گذر، `structure_type` نوع سازه مورد نظر |

مقدارهای select:
- **`facing` جهت**: شمال، جنوب، شرق، غرب، شمال شرقی، شمال غربی، جنوب شرقی، جنوب غربی، فرقی ندارد
- **`floor_preference` ترجیح طبقه** (آپارتمان، آپارتمان اداری، کارخانه): طبقات بالا، طبقات میانی، طبقات پایین، همکف، فرقی ندارد
- **`commercial_location` موقعیت تجاری** (مغازه): بر خیابان، نبش، داخل پاساژ/مجتمع، بازار/راسته، فرقی ندارد
- **`structure_type` نوع سازه** (صنعتی‌ها): خرپا، استاندارد، فرقی ندارد

### ۶. امکانات — چک‌باکس‌های **به‌ازای هر نوع ملک**
| نوع ملک | امکانات |
|---|---|
| آپارتمان / پنت‌هاوس / برج / سوئیت | پارکینگ، انباری، آسانسور |
| خانه ویلایی / ویلا | حیاط، باغ یا فضای سبز، پارکینگ، استخر ۴ فصل، آتشکده، آبنما، جکوزی، آلاچیق، باربیکیو، سونا، سرایداری |
| کلنگی | آب |
| مغازه | بالکن یا نیمه طبقه، کرکره برقی، تابلوخور، سرویس بهداشتی |
| غرفه داخل پاساژ | پارکینگ |
| زیرزمین تجاری | تابلوخور، سرویس بهداشتی |
| باغ و باغچه | چهاردیواری |
| زمین کشاورزی | چاه آب |
| آپارتمان اداری | پارکینگ |
| کارخانه / کارگاه / سوله / انبار / گاراژ | اداری، نگهبانی، جرثقیل سقفی، آب، برق، گاز |
| زمین‌ها (مسکونی/تجاری) | بدون امکانات |

### ۷. اولویت، وضعیت و پیگیری (سطح بالای جدول)
| فیلد | کلید | مقدارها |
|---|---|---|
| فوریت | `urgency` | `low` کم، `normal` عادی، `high` زیاد، `critical` فوری |
| دمای مشتری | `temperature` | `hot` داغ، `warm` گرم، `cold` سرد |
| وضعیت | `status` | `active` فعال، `inactive` غیرفعال، `converted` تبدیل‌شده، `lost` از دست رفته |
| منبع آشنایی | `lead_source` | الزامی — منابع تماس (تبلیغات، رفرانس و...) + `colleague_transfer` انتقال از همکار |
| همکار معرف | `property_preferences.colleague_id` | الزامی اگر منبع = انتقال از همکار |
| مشاور مسئول | `assigned_consultant_id` | از جدول `profiles` |
| یادداشت | `notes` | متن آزاد |
| برچسب‌ها | `tags` | آرایه متن |
| آخرین تماس | `last_contact` | خودکار از تماس‌ها/پیگیری‌ها |
| پیگیری بعدی | `next_followup` | تاریخ |
| تاریخ ثبت | `created_at` | خودکار |
| آخرین به‌روزرسانی | `updated_at` | خودکار |

فیلدهای قدیمی/خاکستری (در داده جدید پر نمی‌شوند — فقط رکوردهای قدیمی):
`first_name`، `last_name` (برای سازگاری با تماس‌ها همگام نگه داشته می‌شوند)،
`customer_type`، `budget_min`، `budget_max`، `min_area`، `max_area`، `bedrooms`،
`required_features`، `preferred_floor`، `parking_required`، `elevator_required`،
`preferred_province_ids`، `preferred_county_ids`.

## جدول‌های پشتیبان (منبع داده‌های ثابت)
- `counties` شهرستان‌ها — فیلتر با `active`
- `neighborhoods` محله‌ها (روباط‌کریم) — فیلتر با `active`
- `cities` شهرها — فیلتر با `active`
- `colleagues` همکاران
- `profiles` مشاوران/کاربران
- `calls` تماس‌ها، `follow_ups` پیگیری‌ها، `activities` فعالیت‌ها، `property_matches` تطبیق‌ها
